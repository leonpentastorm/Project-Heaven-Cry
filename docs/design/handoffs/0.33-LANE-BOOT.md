## Built

1. **The engine out of the boot chunk** (commit `53ae6c2c3`).
   - `game/store.ts` is in the boot chunk and imports only types from the engine. The engine, the game's data and the
     narrator code load on demand: `game/storeEngine.ts` (re-exports what the store uses), loaded by `loadEngine()`.
     `engineReady()` and `loadedEngine()` are exported too.
   - `hostRoom` and `joinRoom` run straight away when the engine is in (the same call stack as before). When it is not,
     they wait for it (`withEngine`). Continue (`resumeSession`, `resumeRoom`), the refresh resume, `takeOver` and a saved
     game all go through those two. `startProvingGround` waits for the engine before `hostRoom`, so its `sandbox/start`
     still comes in the same tick as the room opening. `migrateLoaded`, `apply` and `viewFor` only run once a room is
     open, which means the engine is in.
   - The title has no engine import left:
     - The art lookup has its own module (`game/art.ts`; `screens/shared.js` re-exports it).
     - The provider list and settings checks are engine-free (`narrator/providerList.ts`, and `narrator/models.ts` for
       MODELS and COST_CEILING_USD; `providers.ts` and `anthropic.ts` re-export them).
     - The tips' seen set has its own module (`game/tipsSeen.ts`).
     - The fight-tabs settings page is `React.lazy`.
     - The character files, the credits (the engine's OST table) and the Proving Ground start load on demand through
       `game/lazy.ts` (`lazyModule`, `useLazy`, `withLazy`). The Characters panel warms the character-file module while
       it is open, so Import's file picker still opens inside the click.
   - The problem report reads a room's run summary and cost estimate through `loadedEngine()`. A room always has the
     engine in.
   - The preloader (`game/preload.ts warmCode`) warms the engine and the room overlays from the load event on, from any
     screen.
2. **The effects layer out of the entry chunk** (same commit).
   - Everything App draws over a room's screens is its own chunk: `game/roomLayer.tsx`, `screenLoad.ts ROOM_LAYER`. That
     covers music, Narrator voice, votes, memory, story scroll, FxLayer, turn banners, cut-ins, the Proving Ground's
     panel, mode centre, Narrator seat, mission board, link line and tips.
   - App waits for this chunk before it shows a room's screen, the same way it waits for a screen's chunk, so the
     overlays are always there with a room. They draw in the same order as before. `cue` and `leaveFlow` are reached
     through the chunk.
   - Render counting moved to `game/renderCount.ts`, so `window.__phcRenders` keeps the same names.
3. **Map items** (second commit, **not verified in a browser**, see below).
   - `dc/runtime.tsx same()` compares an item's fields without building key arrays. It returns the same answers as
     before.
   - `screens/combat.js` hands identical values over as the same objects: guard pips (one list per count) and a tile's
     dimmed kit layers (one list per layers and dim, `WeakMap`). This does not change what is drawn.
   - This is the cheap part only. Building each tile only when its own inputs change was not done (see "Not built").

## Not built, and why

- **Each tile built only when its inputs change.** The hover moves many tiles at once: the route arrows, hazard
  crossings, the sightline, the stroke layer and the evoke preview all read `S.hover`. A per-tile cache would have to
  list every input the 150-field tile reads, and missing one leaves a stale tile on the map. This needs `combat.js`
  split first.
- `protodata.json` out of the boot chunk (main.tsx needs only its helmet CSS). Not asked for.
