## Not built, and why

1. **The hood's `seen_range` through `npm run try`:** the hoods and optics are stage B rows (B2); no data row has a
   `stat_mod` today, and `npm run try` cannot add one. Proved instead by a reducer test on a test-only row (wear it,
   start a fight, `statQuery` answers -2). Re-run with `npm run try` once B2 types the hoods.
2. **Wearing a body armour class variant as body armour:** the loader seam is built (item 7957); what wearing such a row
   does (set `armourClass` from its `armour_class`, hold its effects at `worn.torso_outer`) belongs to the uniques patch.
   Today a character's body armour is the class number only; `equip` would put such a row in `worn.torso_outer` and it
   would count for nothing. No line uses it.
3. **The families' rows `vests` and `plate`** in `data/families.json`: A4's file (and a family row needs a maker `line`,
   which no design file gives for Vests or Plate). The class rows carry `family` and `form`; the validator checks a
   class row's family against `families.json` only when that family exists. When A4 or B0 adds the two rows, tighten
   the check (a class row's family must exist) in `tools/validate.py` (the class-rows block).
4. **Client:** `apps/web/src/screens/main.js` `ROMAN` has no VI (a class 6 sheet reads "Class undefined"), and the
   Proving Ground's armour buttons are a typed `[0..5]` (`apps/web/src/game/sandbox.tsx`); `main.js` reads `ARMOUR[n].name`
   (absent, as before: it says "Body armour"). All lane A3's (the card and the sheet). The engine gives
   `ARMOUR_CLASSES` (with names) for them.
5. **Survival does not hand out class 6** (the Forge fits 1 to 5; the camp shelf holds `armour:1`; the shop never holds
   armour): as designed (numbers file: "the breacher plate"; design item 5). Where it should appear is stage B / C.
6. **`run/loadout.ts GEAR_KEYS`** does not copy `wornState`: the camp strips it first (`stripGear`) and the loadout never
   writes it, so nothing is lost. Not touched (not this lane's file).
