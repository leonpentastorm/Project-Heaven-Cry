## Procedure: read this before the first tool call (Leon, 18 Nov: "you used way too much usage before I had to remind you to use the proper procedure")

The last takeover burned usage because the new lead did the work itself. These are not advice. They bind from the
first minute, before Leon has to say it.

1. **The lead does not build, search or run long jobs.** The lead talks to Leon, designs, rules, reviews diffs,
   rewrites player words after looking at screenshots, merges and deploys. Everything else goes down
   (CLAUDE.md "Who does what").
2. **Every agent gets an explicit model, every time:** `haiku` for lookups, greps, counts, re-running a command,
   screenshots; `sonnet` for text, data, docs and mechanical edits from a verified list; `opus` for contained
   building with a test to pass and for reviews of rule changes. An agent call with no `model` is a mistake: it
   inherits the lead's tier and costs the most.
3. **Do not read to get oriented.** Read this file and the attack plan, then only the document a lane names. Do
   not read the chat transcript, do not open source files to "understand the codebase", do not re-scout what a
   scout document already answers (the scout files of 18 Nov say where every change goes).
4. **Before any piece of work costing more than a few tool calls, write the brief instead of starting it:** the
   files to read, the scout section it builds from, the test that proves it done, the model. If the brief cannot be
   written, the lead does not understand the task yet: ask Leon one question, do not explore.
5. **One build workflow at a time unless files do not overlap;** reviewers are `sonnet` unless rules changed. A
   builder that needs a new engine piece reports it at once and builds the rest (it does not stop and wait).
6. **Long commands** (the full check, the browser suites, the replays, a deploy's uploads) are run by an agent or
   in the background, never watched by the lead line by line. Ask for one line back: green, or the failing name.
7. **Say the usage cost before a big step** (a full browser run, a five-agent workflow) when Leon has said usage is
   tight, and pick the cheaper way that proves the same thing (`docs/TESTING.md`: cheapest tool first).
8. **A message to Leon is short:** the result first, what is not done, what nobody has seen on screen.

If a new lead finds itself editing code, grepping the engine or reading a long file in its first hour: stop, and
write the brief.

- Shell: Git Bash; `export PYTHONUTF8=1`; `python` (not python3).
- Gate: `python tools/check.py` (ALL GREEN); `REPLAY_FULL=1 npm test -w @phc/engine -- replay-hash` (29);
  `npm run balance`.
- Browser suites: `export NODE_PATH="C:/Users/Izacarl/Documents/Project Heaven Cry/node_modules"`, then
  `python tools/e2e.py <suites>` or `all --jobs 4`; `KEEP_SHOTS=1` keeps `.check/e2e/shots/<suite>/` (a passing run
  deletes them otherwise). It owns port 8787 and stops every wrangler on the machine: one lane at a time.
  `capture-skills` screenshots the 27 skill pages into `.check/capture/skills/`. `capture-all.mjs` is an unfinished
  draft (not registered): its skill-page selector is wrong.

  `apps/web/src/game/{assets,eyelines,protodata}.json` (`git diff --ignore-cr-at-eol --quiet && git checkout -- .`).
- Re-record recorded tables only on purpose: `GOLDEN_RECORD=1 REPLAY_RECORD=1 REPLAY_FULL=1 npm test -w @phc/engine`.
- Deploy (in the release tree, clean, `origin/main` an ancestor of HEAD): `npm run assets`;
  `python design/canvas-build/build.py --web`; `npm run build`; push HEAD to `develop` and `main`; make a scratch
