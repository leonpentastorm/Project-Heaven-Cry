# The move pool: shelved class moves (dig them up later)

Class Roster Revision 3 (accepted 8 Nov 2026, phase A; `docs/design/class-roster-rev3-proposal.md`) keeps 34 old moves
in the nine base classes and shelves the rest. **A shelved move keeps its data, its handler and its tests.** It just
isn't on any class's list, so nobody can hold it in play. This page lists every shelved move, so the advanced rethink
(proposal section 7) can bring each one back by data alone.

- **Where they live.** The 39 Revision 2 base moves are in `data/classes.json` `move_pool.moves`, under their old
  class ids (`origin`). The advanced moves stay in `advanced[].moves`. Every move carries `origin`, `fantasy_tags`,
  `attributes`, `status` (`active` or `shelved`) and, when shelved, `future_home`.
- **Keys don't change.** A move runs under `class:<origin>.<moveId>` whichever class names it. A class's rank lists it
  as `{"ref": "<origin>.<moveId>"}`, so bringing one back is a single line in a class's `ranks`.
- **Tests keep running.** Revision 2 test files call `useRevision2Classes()` (`packages/engine/test/helpers/legacy.ts`).
  It turns on two test-only switches: the 13 old classes, and the advanced classes.
- **Engine state** below was checked against the code on 8 Nov 2026. A registered handler is in `src/classes/*.ts`. The
  test column names the files that exercise the move (by key or by name).
- **Future home** follows the roadmap (proposal section 7). Batch 1 is the nine squared classes. Batch 2 is the ring of
  nine hybrids. Batch 3 is the other 18 hybrids. Each class's `pair` / `kind` / `batch` is in its data entry.
