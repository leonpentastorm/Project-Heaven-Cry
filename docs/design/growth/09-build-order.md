# The growth bible: the build order (0.34 rebalance, closing pass; pass 4 by section G)

The bible is applied in the seven steps of `README.md`, **one after another, with the gate between each**. A step starts only when the step before it is green and reviewed. **No two steps run at once, and inside a step no two lanes run at once on the same file**: the lanes marked "after" run one after another because they share files, and a step with no lanes is one lane. The lead writes the rules revision in `docs/rules/PHC-Core-Rules-v1.0.md` at the start of each step (the spec first, then the data, then `python tools/validate.py data`), before any lane begins; no lane edits the spec.

**Ruling 50: every step's proof uses only what that step and the steps before it have built.** Where a check (a) line needs a piece a later step builds, the proof here names the narrower line it can prove, and the full line is proved in the step that completes it.

Rules every brief carries (CLAUDE.md): use the engine, never build beside it; the no-rebuild rules 1 to 6 (a new piece only from `08-primitives.md`, approved by the lead; content is data; one copy of every rule and price; a consolidation pass; tests through the real path, the reducer and a real action; lint baselines only shrink); every mode keeps its side panels. Every number is the bible JSON's: a builder copies it from `tools/balance/bible/*.json` (or its `@` reference) into `data/`, never from a prose file. **The gate of every step** is `npm run check`, `python tools/balance/check.py` (still `0 FAIL, 0 WAITING`), and the step's own proving test; golden tables re-record **on purpose**, with the diff read against `TABLES.md` before it is accepted.
